🚀 Getting Started

What is ISRAP AIRMAPS Intelligence Studio?

The Intelligence Studio is a research-grade local web application for exploring, auditing, and correcting EPA AQS air quality monitoring data collected across six stations in San Antonio, TX (2019–2024). It combines ERA5 reanalysis meteorology with 14 anomaly detection algorithms and 8 imputation methods in an interactive, reproducible workflow designed for NASA/ISRAP graduate research.

📡

6 AQS Stations

Sites 32, 52, 59, 1069, 1080, 1087 — hourly CO, NO₂, O₃, PM₂.₅, SO₂

🔍

14 Anomaly Methods

From simple IQR to deep learning Anomaly Transformer and OmniAnomaly

🩹

8 Imputation Methods

Linear through ERA5 regression to BRITS, SAITS, CSDI, ImputeFormer

🌤️

ERA5 Meteorology

Temperature, humidity, wind, pressure, BLH — 52,600 hourly rows

Launching the App

Open a terminal, navigate to the project directory, and run:

cd israp_airmaps_intelligence_studio
python -m streamlit run app.py

The app opens automatically at http://localhost:8501. Keep the terminal open while using the app. To stop it press Ctrl+C.

ℹ️
First load is slow. On first load the app reads all 6 station CSVs and the ERA5 file (~300 MB total) into memory. Subsequent navigation between pages is fast because data is cached with @st.cache_data.

The "Run" Button Pattern

All computationally expensive operations (anomaly detection, imputation, benchmarking, pipeline) require pressing an explicit ▶ Run button. Adjusting sliders or dropdowns does not automatically re-run analysis — this prevents accidental long computations and lets you configure all parameters before committing.

💡
Results persist within a session. Once you run a computation, its results are stored in Streamlit session state. You can navigate to other pages and come back — results will still be there. They reset when you refresh the browser or restart the Streamlit server.

🔬 Scientific Safeguards

The Studio enforces six non-negotiable scientific rules throughout every workflow:

  1. Raw data is never overwritten. Source CSV files are read-only. All transformations (anomaly flags, imputed values) are stored in new columns or separate output files.
  2. Structurally missing channels are excluded. If a station-pollutant pair has less than 1% valid (non-NaN) observations, it is classified as "Not monitored at this station" and excluded from all anomaly detection and imputation workflows.
  3. Negative values are flagged, not zeroed. Physically impossible negative concentrations are preserved with their original values and marked with a separate is_negative flag column. Zeroing them would bias statistical analyses.
  4. Station 3 SO₂ is excluded by default. Site 59 exhibits ~33% negative SO₂ readings — systematic sensor corruption. The app marks this channel as corrupted and excludes it from pipeline runs. See Page 09 for full diagnostics.
  5. Chronological train-validation-test splits only. All ML models (LOF, Isolation Forest, BRITS, SAITS, etc.) are trained on past data and evaluated on future data. Random shuffling of time-series data is never used.
  6. Reproducible seeds. Every experiment stores its random seed. Results can be reproduced exactly by re-running with the same configuration from Experiment History.
⚠️
Station 3 SO₂ — Do not use in final models. Even if the "experimental repair" option on Page 09 produces visually plausible values, the underlying data is fundamentally compromised. Results from this channel should not be cited in publications without explicit disclosure and justification.

Anomaly Lab

The Anomaly Lab is where you detect anomalies in a single station-pollutant time series. Choose from 14 methods, tune parameters, press Run, then inspect flagged points individually and mark each as a True Positive, False Positive, or Uncertain before it enters the pipeline.

📷
Anomaly Lab page: method selector dropdown showing "IQR Fence" selected. Below: parameter slider for k-factor (1.5–4.0). Large time-series chart with red diamond markers on flagged anomalies. Sidebar shows n_flagged=558, pct_flagged=1.2%, runtime=0.04s.
Screenshot: Anomaly Lab — IQR detection on CO at Station 4

Available Methods

IQR Fence Hampel Filter Rolling Z-Score STL Residual SCREEN Physical Constraints LOF Isolation Forest LSTM NDT Anomaly Transformer DCdetector OmniAnomaly USAD Ensemble

How to Use

  1. Select a Station and Pollutant from the dropdowns at the top.
  2. Choose a Detection Method. Parameter sliders for that method appear immediately below.
  3. Optionally set a Date Range to focus on a specific period.
  4. Press ▶ Run Detection. A spinner shows progress (deep learning methods may take 5–60 seconds on CPU).
  5. Review the flagged time series. Hover over red markers to see the timestamp and value.
  6. Open the Detail Drawer to inspect individual anomalies one by one.
  7. Use the Review Workflow buttons to mark each anomaly: ✅ True Positive / ❌ False Positive / ❓ Uncertain. Reviews are saved to the SQLite store.

Page 05

Anomaly Comparison

Run multiple detection methods simultaneously on the same data and compare their outputs systematically. The Anomaly Comparison page is designed for method selection: before committing to a single detector for the final pipeline, use this page to understand where methods agree and disagree.

📷
Anomaly Comparison page, "Overlap Analysis" tab: a Jaccard similarity heatmap showing pairwise agreement between 5 methods (IQR, Hampel, Rolling Z-Score, LOF, STL). High similarity shown in dark teal, low in light yellow. Methods with high Jaccard scores are highlighted.
Screenshot: Anomaly Comparison — Jaccard Similarity Heatmap

Tabs

  1. Method Summary — table of flagged counts and percentages for each method, horizontal bar chart for quick visual comparison, status badges (OK / warning / error).
  2. Overlap Analysis — Jaccard similarity matrix (how much do two methods agree on which points are anomalous?), co-flagging heatmap (how often are pairs of time points flagged together?).
  3. Timeline — raw signal plotted once, with coloured markers for each method's flags stacked below, plus an "agreement count" bar showing how many methods flagged each point simultaneously.
  4. Ensemble — combine all methods into a union (any method flags), majority-vote, or all-agree ensemble. Shows ensemble confidence (fraction of methods agreeing) and a confidence-coloured timeline.
  5. Scorecards — one card per method showing flagged count, runtime, status, and a normalised performance score relative to the other methods in the run.
  6. Download — download flagged-only CSV, full annotated CSV with per-method flag columns, and summary CSV.
💡
Interpreting Jaccard scores. A high Jaccard score (≥0.5) between two methods means they are flagging largely the same points — you can use either interchangeably. A low score (<0.2) means they are detecting different phenomena. In that case consider using an ensemble or investigating what each method is sensitive to.

Imputation Benchmark

The Imputation Benchmark page runs controlled masking experiments to objectively compare imputation methods. Unlike the Imputation Lab (which fills real gaps), the Benchmark artificially masks known values and measures accuracy against the ground truth — giving quantitative metrics you can cite in research.

📷
Imputation Benchmark — Gap-Length Heatmap tab. Methods on y-axis (Linear, ERA5 Ridge, MICE, BRITS), gap lengths on x-axis (1h to 168h). Cells coloured green-to-red (lower MAE = greener). Star ★ marks best method per column. BRITS wins at 48h–168h; Linear wins at 1h–6h.
Screenshot: Imputation Benchmark — Gap-Length Heatmap

Three Tabs

📊 MCAR Leaderboard

Randomly masks a percentage of observed values (Missing Completely At Random), runs each selected method, and ranks by MAE. Shows:

  • Leaderboard table with MAE, RMSE, SMAPE, R², Bias, Reps (best row highlighted green)
  • Grouped bar chart: MAE & RMSE side by side
  • MAE vs R² scatter plot for trade-off visualisation

🔥 Gap-Length Heatmap

The most important benchmark for gap imputation research. For each combination of method and gap length [1h, 2h, 6h, 12h, 24h, 48h, 72h, 168h], masks a contiguous block of that length and measures accuracy. Shows:

  • Annotated heatmap (★ = best method for that gap length)
  • Best-method-per-gap-length summary table
  • Degradation line chart: how each method's accuracy deteriorates as gaps grow

🎭 Missingness Scenarios

Compares three realistic missingness mechanisms:

  • MCAR — uniform random masking (ideal baseline)
  • MAR — 80% of masked values drawn from above-median readings (simulates sensor dropout during pollution episodes)
  • MNAR — 80% from above-90th-percentile readings (sensor saturation causing data loss during peak events — hardest to impute)
⚠️
Benchmark runtimes. The Gap-Length Heatmap runs up to (n_methods × 8 gap lengths × n_trials) computations. With 4 methods and 3 trials per cell that is 96 imputation runs. Expect 2–10 minutes for deep learning methods. Select only the methods you need and keep trials at 2–3 for exploratory runs.

Final Pipeline

The Final Pipeline orchestrates all stages end-to-end in a single run. Configure your station selection, anomaly method, ensemble threshold, and imputation method, then execute the full 9-stage workflow and download all outputs as a single ZIP file.

📷
Final Pipeline page: top section shows a horizontal flow diagram with 9 boxes (Load → Audit → Gap Analysis → Anomaly Detection → Ensemble → Review Filter → Imputation → Export → Report) connected by arrows. Each box colour-coded by status (green=done, grey=pending, amber=running).
Screenshot: Final Pipeline — Flow Diagram and Stage Cards

Pipeline Stages

#StageWhat it does
1LoadRead selected station CSVs and ERA5 file
2AuditCompute completeness, negatives, structural flags for each station-pollutant pair
3Gap AnalysisDetect and classify all data gaps (very_short / medium / long / very_long)
4Anomaly DetectionRun the selected anomaly method on all non-structural station-pollutant pairs
5EnsembleApply majority-vote or union ensemble if multiple methods were run
6Review FilterExclude anomalies that were manually marked as False Positives in the Anomaly Lab
7ImputationFill detected gaps using the selected imputation method; flag anomalies for exclusion
8ExportWrite per-station CSVs with anomaly flags and imputed values to the exports/ directory
9ReportGenerate Markdown and HTML audit reports summarising the full pipeline run

How to Run

  1. In the Configuration Panel, select which stations to process and which anomaly + imputation methods to use.
  2. Check the Pre-run Summary — it shows how many station-pollutant pairs will be processed and estimated runtime.
  3. Press ▶ Run Pipeline. A live progress bar updates as each stage completes.
  4. Review Stage Result Cards — green = success, amber = warning (partial results), red = error.
  5. Use the Download ZIP button to get all output CSVs and the pipeline manifest JSON.

📖 Glossary

AQS
Air Quality System — EPA's national ambient air quality monitoring network
ERA5
ECMWF Reanalysis v5 — global hourly atmospheric reanalysis dataset used here as meteorological context
MCAR
Missing Completely At Random — data is missing independently of observed or unobserved values (easiest to impute)
MAR
Missing At Random — probability of missingness depends on observed values (e.g. sensor drops out more at high concentrations)
MNAR
Missing Not At Random — missingness depends on the unobserved value itself (hardest to impute without external information)
Structural Missingness
A station-pollutant pair with <1% valid observations — the instrument was never deployed or permanently failed
IQR
Interquartile Range — Q3 − Q1. Used in the IQR Fence detector: flag values outside [Q1 − k·IQR, Q3 + k·IQR]
STL
Seasonal and Trend decomposition using Loess — separates a time series into trend, seasonal, and residual components
LOF
Local Outlier Factor — compares the local density of a point to its neighbours; density-based anomaly detection
SCREEN
Rate-of-change detector — flags consecutive hourly observations that change faster than a physically plausible speed limit
BRITS
Bidirectional Recurrent Imputation for Time Series — bidirectional LSTM with decay weighting for missing data (Cao et al. 2018)
SAITS
Self-Attention-based Imputation for Time Series — transformer-style attention imputer (Du et al. 2023)
CSDI
Conditional Score-based Diffusion model for Imputation — denoising diffusion probabilistic model adapted for time series gaps (Tashiro et al. 2021)
ImputeFormer
Low-rank attention transformer for time series imputation — efficient attention via low-rank factorisation
MICE
Multiple Imputation by Chained Equations — iteratively imputes each variable conditioned on all others; produces multiple plausible imputed datasets
BLH
Boundary Layer Height — the ERA5 variable measuring the depth of the turbulent mixing layer; low BLH traps pollutants near the surface
Gap Category
very_short (1–2h), medium (3–24h), long (25–168h), very_long (>168h) — used to select appropriate imputation methods
Jaccard Similarity
|A ∩ B| / |A ∪ B| — fraction of time points where two methods agree. Used in the Anomaly Comparison overlap analysis.
MAE
Mean Absolute Error — average |predicted − true| over all imputed points
SMAPE
Symmetric Mean Absolute Percentage Error — scale-free error metric: 100 · mean(|p−t| / ((|p|+|t|)/2))
RMSE
Root Mean Squared Error — √(mean((predicted − true)²)); penalises large errors more than MAE
